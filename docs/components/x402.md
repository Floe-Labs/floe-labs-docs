# 05 · Payment facilitator `GA`

Floe pays any vendor API per call from your agent's prepaid balance through one endpoint. You fund the agent once; the facilitator pays each vendor as your agent calls it — enforcing your spend controls on every request. Your agent never handles a wallet, a signature, or a settlement.

Under the hood, the facilitator reaches **thousands of vendor API services** that use the [x402 payment protocol](https://github.com/x402-foundation/x402), signs the payment, and returns the vendor's response to your agent. Your agent just calls `fetch()`.

```typescript
const response = await agentkit.run("x402_fetch", {
  url: "https://api.example.com/premium",
  method: "POST",
  body: { prompt: "..." },
});
```

For the full endpoint reference — the `POST /v1/proxy/fetch` proxy, per-call cost headers, spend controls, idempotency, and the settlement lifecycle — see the developer guide:

- [Payment Facilitator (developer guide)](../developers/x402-facilitator.md)

## How it works

```
Agent → credit-api.floelabs.xyz/v1/proxy/fetch → target API
              ↑                       ↑
        Signs + settles          Returns 402
        on Floe's facilitator
        contract
```

When the target API returns HTTP 402, the facilitator funds the payment from your agent's prepaid balance and re-requests. The agent only sees the final response.

## Server-side spend controls

- **Spend limits** — per-session caps via `set_spend_limit`.
- **Allowed destinations** — lock the facilitator to a list of endpoints or contracts.
- **Verify-work-before-pay** — the facilitator can require the work hash to match a commitment before settling.
